Powers Tool WebUI

Powers Tool 的 FastAPI 與靜態資源 WebUI adapter。

WebUI 是不綁定特定廠牌的產品介面；目前 Product support 僅限 Supported Models 所記載的 Product-active exact scopes；未知或未註冊的 live hardware 會在 Core 中 fail closed。

本 README 說明 WebUI 行為、API、驗證與維護者邊界。一般操作員工作流程請參閱 WebUI 使用者指南；開發人員與 agent 的 UI 變更規則請參閱 WebUI 變更規則。

WebUI 與 CLI 是建立在共用 Core runtime 之上的平行產品介面。

Product 支援邊界

Product model selector 僅包含 Product-active 型號。GW Instek PSM-2010 的 Product LIVE scope 僅限 ASRL / RS-232 + system VISA，並開放 Core Product matrix 所列的 23 個 model-aware commands，包括 setpoint／output、protection、 snapshot／restore、ramp 與 software sequence workflows。Powers Trigger commands 仍不支援；其他 transport 與 backend 仍會 fail closed。完整範圍以 Supported Models 為準。

WebUI 內建於單一 powers-tool 發行套件中，同時保留 powers_tool_webui 的 import 邊界。它依賴共用的 powers_tool_core runtime 與發行套件的 webui extra。前端由靜態 index.html、styles.css，以及以 app.js 為 bootstrap／composition root 的原生 JavaScript modules 組成；執行或建置 frontend 不需要 Node toolchain。

  • api.js 擁有共用的 JSON HTTP request/response 邊界；execution-context.js 擁有純 execution/workspace context；state.js 擁有初始 page-local state；device-resource.js 擁有 Device/Resource 與 execution-mode 控制項；command-form.js 擁有命令目錄／表單渲染、payload 建構與參數限制。
  • results.js 擁有 job-result summary 呈現；jobs.js 擁有 Job HTTP 提交、SSE transport 與 Job History；live-data.js 擁有 Live Data 取樣、lifecycle 與通道呈現；json-files.js 擁有共用的 JSON file picker 與下載 helper。
  • ramp-list.js、trigger-list.js、sequence.js 與 snapshot-restore.js 分別擁有各自文件的純 materialization 與驗證；workflows.js 擁有瀏覽器端 Ramp List、Trigger List、Sequence、Snapshot 與 Restore 編輯器及其 JSON Load/Save orchestration，文件 schema 仍由各自的 focused document modules 擁有。
  • basic-controls.js 擁有 Basic 控制動作與 Live-readback 呈現；command-support.js 擁有 command-support 與 channel-capability 呈現；i18n.js 擁有 locale 驗證、catalog lookup、English fallback 與 interpolation；locale_ui.js 擁有瀏覽器語言偵測、locale 偏好儲存、<html lang> 與 runtime 語言控制項；locale_en.js 與 locale_zh_tw.js 分別提供 English source catalog 與維護中的 Traditional Chinese catalog。

app.js 維持 bootstrap 與 composition root：controller factory 參數僅代表跨模組邊界提供的相依性，某個 controller 擁有的 helpers 彼此直接呼叫，不會繞回 app.js 路由。Frontend tests 包含 native module-graph smoke，會在不改寫 import/export 的前提下匯入真實的 app.js graph root；既有 global compatibility harness 仍可用於更廣泛的 frontend 行為測試，但不取代 native graph 檢查。

套件與進入點 (Package And Entry Point)

WebUI 提供兩個已安裝的 console command：

  • powers-tool-webui：啟動本機 FastAPI 伺服器。
  • powers-tool-webui-launcher：啟動 Windows GUI 啟動器。

本機 shared PyInstaller onedir bundle 包含 dist\powers-tool\powers-tool.exe、dist\powers-tool\powers-tool-webui-launcher.exe，以及供 source-mode Electron Desktop shell 使用的 private dist\powers-tool\powers-tool-webui-host.exe；三者共用 dist\powers-tool\_internal\ 目錄。Desktop Host 不是新的公開 CLI entry point。Shared bundle artifacts 與已安裝的 console wrappers 分開，不會重新命名或取代任何 installed entry point。

Environment

根目錄的 README Install guide 是 canonical setup reference。從 repository 根目錄準備 WebUI runtime：

uv sync --extra webui --locked --link-mode=copy

若要執行測試或 PyInstaller build，請使用 locked development environment：

uv sync --all-extras --locked --link-mode=copy

Localization

維護中的 locale 是 en 與 zh-TW；English 是來源與 fallback locale。切換會在執行階段生效且不重新載入頁面，只改變瀏覽器呈現，不得建立 HTTP request、Job、workflow action 或 EventSource side effect。Machine values、API schema、command IDs、model IDs、VISA resources、SCPI 與 raw diagnostics 保持原值。

語言偏好使用獨立的 browser storage key powers-tool.webui.locale。即使 storage 不可用，也會安全 fallback，不影響 WebUI 的正常操作。

Header 右上角提供「外觀」與「語言」兩個標示清楚的控制項。語言控制會顯示目前 locale（English 或 繁體中文），accessible name 則描述切換目的地。外觀控制會顯示目前的主題偏好，並依序切換 System、Light、Dark。主題偏好會以一年的 Max-Age 儲存在 powers-tool.webui.theme cookie，並由 browser WebUI 與 Electron shell 共用。System 模式遵循 prefers-color-scheme；Electron shell 會使用同一個 loopback cookie 同步 native window theme。

選定的主題會套用至 WebUI 主要的 panels、cards、fields 與 status surfaces，不只改變頁面背景。

深色主題下，主要控制項、狀態文字，以及不可用或停用的控制項，會在深色 surface 上維持足夠辨識度。

Job Parameter Admission

POST /api/jobs 頂層只接受 command、runtime、parameters 與可選的空 artifacts；未知的頂層欄位會回傳 HTTP 400。

parameters 必須先通過 Core 擁有的命令契約，才會排入工作或取得硬體鎖。WebUI 不重複維護各命令 allowlist、alias 或型別強制轉換。錯誤的精確型別、非法 null、未知／不適用欄位與 alias conflict 都會回傳 HTTP 400，而不是伺服器錯誤；實際執行的是 admission 後的 canonical request。

用途

WebUI adapter 以 powers_tool_core 的共用 Core runtime 為中心，提供本機 FastAPI 與瀏覽器介面。

WebUI 負責瀏覽器與靜態資源、FastAPI route shape、Tkinter launcher、面向瀏覽器的序列化、Job 提交與 SSE 呈現、Live Data 顯示、資源掃描，以及命令 metadata 呈現。

Core 負責 SCPI 與儀器 I/O、Runtime 驗證與 dry-run 規劃、輸出／保護／觸發／Sequence／Ramp／Snapshot／Restore 行為、安全限制、型號與 planning-profile metadata，以及 Stop、取消、release/local、session close 與 cleanup。

WebUI 必須使用 Core 公開 API，不得 import CLI adapter 程式碼，也不得重新實作儀器行為。

執行

從 repository 根目錄執行：

uv run python -m powers_tool_webui.server --host 127.0.0.1 --port 7999

開啟 http://127.0.0.1:7999/。除非刻意要把伺服器暴露到本機以外的網路，否則請保持 host 為 127.0.0.1。

已安裝的 Windows console wrappers：

# FastAPI server console wrapper
.\.venv\Scripts\powers-tool-webui.exe --version
# GUI launcher console wrapper
.\.venv\Scripts\powers-tool-webui-launcher.exe

無參數啟動時，launcher 會保持隱藏，從 7999 開始最多嘗試 100 個連接埠（通常到 8098），並以實際 bind 測試每個候選。新服務通過 /api/health readiness 後才開啟瀏覽器與 Running 視窗。

--port 9000 只嘗試固定連接埠；加上 --auto-port 才會從指定值繼續自動嘗試：

.\.venv\Scripts\powers-tool-webui-launcher.exe --port 9000
.\.venv\Scripts\powers-tool-webui-launcher.exe --port 9000 --auto-port

只有全部自動候選都因 address-in-use 失敗時，才會顯示完整 port fallback 視窗、回報嘗試範圍並允許手動輸入其他 port；手動重試若也 address-in-use，視窗保持開啟並重新啟用欄位與 Start。自動候選不會超過 port 65535。非 address-in-use 的 bind 失敗、application initialization、server-thread early exit 與 readiness timeout 都是 fatal startup failure：launcher 保留原始錯誤細節、要求部分建立的 server 停止、關閉自有 socket 並以非零狀態結束；這些失敗永不重新開啟 manual port window，包括發生在手動 fallback retry 時。

Quit 會先要求取消所有活動中的 WebUI 工作（包含 Live Data、Simulate 與 Dry-run workflow），等待正常清理，再停止 launcher 擁有的伺服器。若清理或關閉逾時，launcher 會保持開啟並回報 shutdown incomplete。精簡／fallback 呈現不改變 port 選擇、startup 失敗分類、cleanup 或 process exit-code 行為。

本機 shared PyInstaller GUI artifact 是位於 dist\powers-tool\powers-tool-webui-launcher.exe 的獨立執行檔；它由同一份 launcher implementation 建置，但不是安裝的 server wrapper。

API

  • GET /api/health：伺服器與硬體鎖狀態。
  • GET /api/commands：命令 metadata、確認旗標、WebUI 限制，以及 Core 衍生的型號與精確實機支援摘要。
  • POST /api/jobs：以 command、runtime、parameters 與可選 artifacts 提交工作。
  • GET /api/jobs/{job_id}：讀取目前工作狀態。
  • POST /api/jobs/{job_id}/cancel：提出取消要求。
  • GET /api/events?job_id=...：Job SSE stream。
  • POST /api/live：啟動實機唯讀輪詢。
  • GET /api/live/{job_id}/events：Live Data SSE stream。
  • POST /api/live/{job_id}/stop：停止 Live Data 輪詢。

/api/commands 的實體 metadata 只會以 canonical model_id 作為 command_support_by_model_id、live_support_by_model_id、channel_capabilities_by_model_id、electrical_ratings_by_model_id 與 setpoint_ranges_by_model_id 各 map 的 key；非實體 profile（例如 generic-scpi）位於獨立的 planning_profiles 物件，不會混入實體型號 map。其 metadata 直接由 Core projection 而來，WebUI 只負責隨 command response 序列化。Evidence 與私有支援 metadata 不會對外暴露。

/api/health 的 package 保留 adapter 識別碼 powers-tool-webui，version 則來自單一已安裝的 powers-tool distribution。

Runtime 邊界 (Runtime Boundary)

WebUI 不 import powers_tool_cli，也不直接執行 VISA 或 SCPI；它把 HTTP payload 對應到 Core 的 RuntimeOptions 與 request objects，再呼叫 powers_tool_core.command_runner。

真實硬體工作由單一硬體鎖序列化；Simulate、Dry-run、離線 metadata 與 Live Data 工作不占用該鎖。同步 Core 執行位於 worker thread，因此 FastAPI event loop 仍可服務 health、工作狀態、取消與 SSE。

Raw /api/jobs 使用 V2 runtime identity：Dry-run 必須且只能提供 planning_model_id 或 planning_profile_id 其中之一；Simulate 只接受實體 planning_model_id；Real 只接受可選的 expected_model_id。Core 會查詢 *IDN?、解析廠牌與型號，並在命令特定 SCPI 前檢查預期型號；安全護欄永遠不能覆蓋 IDN 選出的實際驅動程式。

Legacy runtime.model_profile 與 runtime.model 會被拒絕。WebUI 不會從看似真實或虛假的 resource string 猜測規劃型號；請提供 V2 planning field，或使用 deterministic SIM resource（例如 USB0::SIM::E36312A::INSTR）。WebUI 的 live resource 支援由 scan/job IDN metadata 學習而來。

Raw runtime 值採嚴格型別：boolean 欄位只接受 JSON true／false，"false" 之類的字串無法滿足 confirmation 或啟用模式；integer、string、identity 與 serial-option 欄位同樣在提交前驗證。Raw parameters.channel 只接受 exact 正整數或支援命令的 exact "all"，boolean、float 與數字字串不會被轉型。未知命令與刻意不支援的命令也會在 job/task 建立前同步拒絕。

Browser 與 raw WebUI jobs 一律使用 product support-policy mode；validation-policy runtime 欄位會被拒絕而非忽略。Frontend 的 enabled 狀態僅供 UX，Core 仍是最終由 IDN 選擇的 exact-scope authority。

對 Ramp、Ramp List 與 Sequence，主要 Run 按鈕是有狀態的：Run、Starting...、紅色 Stop、Stopping...，直到 terminal SSE event 確認作用中 job 已清除才回到 Run。清理執行期間顯示 Waiting for safe-off and cleanup，並保持命令切換與 Live Data 硬體存取封鎖；SSE 中斷透過 job-status reconciliation 處理。

瀏覽器的 Real、Simulate 與 Dry-run 都是頁面內狀態；重新載入時一律回到 Real，且不把模式、身分或實機寫入授權存入 browser storage。No-hardware request 會省略 live resource、serial options、expected-model guard 與 confirmation。

取消執行中的工作會先進入非終止狀態 cancel_requested；WebUI 保留 active_job_id 與硬體鎖，直到 I/O 與 Core 清理結束。之後才進入 cancelled；清理失敗則為 failed。

使用者介面 (UI)

靜態 UI 是三區塊儀表板：上方連線與版本區、Basic command 與可折疊 command rail、以及 Live Data、Job History 和結果 JSON 的右側面板。命令 ID 保持 kebab-case；面向使用者的名稱使用空格與 sentence case。

連線區域包含 Supported devices / 支援裝置 唯讀清單與 Device options（裝置選項）。Device options 提供 Real、Simulate、Dry-run 與 Real 模式的 Expected model。Auto-detect 依連線儀器 IDN 判定；Require <model> 只建立預期型號護欄與前端規劃提示，不會覆蓋 IDN 選出的驅動程式。Supported devices 列出目前 Product-open 且 WebUI 可使用的 system_visa 連線。頁面會分別顯示已偵測型號、Expected model、transport/backend 與支援內容。

Real 模式使用頁面內的寫入授權。非空白資源會為目前的資源、Expected model 與偵測型號內容建立預設啟用的授權；Device options 可鎖定寫入。資源或身分內容改變時會建立新授權內容。標題中的 Writes locked／enabled 只是狀態顯示。

前端可隱藏或停用不支援命令，但這只是 UX；直接呼叫 /api/jobs 仍必須通過 WebUI backend 與 Core 的精確 model/command/transport/backend/feature gate。WebUI 是 Product-only，標準瀏覽器使用預設 system-VISA backend，沒有 validation mode 或 backend selector。

瀏覽器會區分 profile support 與 exact Product-mode live availability。在真實資源回傳 capabilities 之前，commands 保持 model-planning 行為並顯示連線 scope 尚未評估。在已 Product-open 的 scope 上成功執行 resource-backed capabilities，或成功的真實 identify，會加入 IDN 偵測的 model、正規化 transport/backend scope 與 per-command exact status；diagnostic 路徑在 expected-model guard 下讀取身分，但不開放 pending feature commands。pending 或缺少的 exact scopes 以不同原因顯示停用，identity/status diagnostics 則明確屬於 policy-exempt。更換 resource 會清除 exact context。

若成功的 identify／verify 偵測到未知或已移除的 model，diagnostic 結果仍可用，但 support projection 為 unevaluated 且不含 command availability；這會清除過期 exact context，也不啟用 Generic fallback。Expected-model mismatch 仍在附加支援 metadata 前使 diagnostic 失敗。Device / Resource summary 亦顯示精簡的 validated/pending/unavailable 計數；pending metadata 只在實際 transport/backend 符合已註冊 pending scope 時出現。

安全的 Core projection 可為 exact scope 附加 sequence_action 與 trigger_source inventories，只暴露狀態與 Product availability，不暴露 evidence 或內部 notes。Projection contract 為 schema version 2：已評估結果使用 canonical model_id；unevaluated diagnostics 將回報的 manufacturer/model 與可為 null 的 resolved model_id 分開，且永不暴露 evidence IDs、歷史路徑、checksums 或 private notes。由於文件與 trigger request 在執行時選擇 feature，command rail 維持 command-level，不會因其他 feature pending 就全域停用命令。純 offline utilities 與 identity/status diagnostics 分類不同，不是 policy-exempt 的硬體 diagnostics。

Basic set 可只設定 Voltage、Current 或兩者。空白欄位會從 payload 省略。Voltage 是輸出電壓設定點，Current 是輸出電流限制／設定值（E36312A、EDU36311A、E3646A）。/api/commands 提供官方 setpoint programming-range metadata；E3646A 對 LOW/P8V 與 HIGH/P20V 是 range-dependent，目前 WebUI 不依此新增 range selector，也不引入硬性小數位數拒絕或靜默 rounding/truncation。E3646A 使用一個全域輸出開關：CH1／CH2 的輸出控制會顯示由 ALL 控制，但各通道的 Voltage、Current 與 Set 仍保持獨立；readback 未知時 ALL 控制項仍可用並送出 output-on。

Ramp 的 Channel selector 會依目前型號 metadata 動態顯示單一通道、通道組合與 All。單一選項送出 channel；組合與 All 送出明確、canonical 的 channels 清單。所有所選通道共用相同 Ramp 參數，並以 lockstep logical steps 前進。全寬的多通道提示只會在選取通道組合或 All 時顯示於 Channel 與 Current 下方；選取單一通道時不會保留空白提示列，其餘 Ramp 參數會維持雙欄對齊。

Ramp List 編輯器最多 10 個有序 segment，可載入 v2 至 v5，並一律儲存 strict v5；每個 Segment 可依目前型號選擇不同通道組合，All 會寫成明確的 canonical channels 清單。Sequence 編輯器最多 250 步，儲存 strict v2 且永不序列化內部 camel-case 狀態名稱。兩者都明確包含 loop_count。對 Ramp 與每個 Ramp List segment，Wait between steps (ms) 只在非最終 voltage step 後套用；Ramp List 的 Wait after final step (ms) 在最後一步之後、segment 完成之前套用。

Ramp、Ramp List 與 Sequence 的 Loop count 在啟用時接受 2 至 10,000；Core admission 另限制最多 1,000,000 個 logical execution units，超過 100,000 時 UI 會顯示長時間執行警告，工作透過既有 Job/SSE stream 發布整數百分比進度，結果 detail 最多保留前 100 與後 100 筆並附加 truncation metadata。關閉 Loop 會移除欄位、使 effective value 變為 1，並將已選的 Loop-complete pulse 重設為 None；無效的已啟用 count 會在重新渲染時保持可見，並讓 Run 與 Save 維持停用直到修正或關閉 Loop。

脈波工作流程

Cycle Output 可選 finished pulse；Ramp 的 Pulse timing 為 None、Every step、Ramp complete 或 Loop complete；Ramp List 為 None、Every step、Segment complete 或 Loop complete；Sequence 只保留 per-Step Trigger pulse。多通道 Ramp List 的 step/segment pulse 每次只發一次，使用該 Segment 第一個 canonical channel；Loop-complete 使用最後一個 Segment 的第一個 canonical channel，且使用者不能設定此 anchor。

E3646A 的輸出啟用為全域控制。Ramp List 會先為清單中會使用到的每個通道寫入第一組安全設定值，再一次啟用全域輸出；WebUI 只在 E3646A context 顯示此提示。

後面板 pulse pin 與輸出通道互相獨立，且只支援 E36312A。當已知所選資源確定是其他型號時控制項停用；身分未知時脈波詳情仍可設定，但 Run 會被封鎖並顯示 E36312A planning/support 指引。完成脈波是軟體排程的後續 *TRG，不是 native LIST；它會暫時修改並還原 trigger／rear-pin 設定，而全域 *TRG 可能影響其他已 arm 的 BUS 行為。Sequence Trigger pulse 的 Leave configured 只控制這些設定是否在脈波後還原。

觸發執行

Trigger Fire 會對所有已 arm 的 BUS trigger 發送全域 *TRG。Trigger Step/List 使用 Immediate 時會在送出 INIT 即啟動，因此 Fire now 會被清除並停用。BUS 的 Wait complete 必須在同一命令中搭配 Fire now；不等待完成的 LIST 則必須選擇 Leave configured。

Trigger List 工作區

Trigger List 使用三通道工作區，每個通道保留自己的 count 與 1 至 100 個 step row，包含 Voltage、Current、Dwell、BOST 與 EOST。Run 只提交所選通道；Load/Save 使用 strict powers-tool-trigger-list-workspace version 1 JSON。

Live Data 樣本包含解析後型號與各通道 OVP/OCP trip state。新鮮且明確的 trip 狀態會對該通道的直接輸出命令加入 WebUI soft guard；過時或未知狀態不加入保護，safe/off 與復原命令仍可用。Advanced Diagnostics 提供 Clear Status / Errors、Get capabilities、Read device information 與 Read errors。Workspace 為每個完整執行 context 保留最新成功結果：Real 包含 resource、Expected Model guard 與解析後 canonical identity，Simulate／Dry-run 包含其 physical planning model 或 planning profile；Result Detail 保留完整 raw job payload。

PSM-2010 的 CH1 卡片會額外顯示目前實際 LOW/HIGH 輸出檔位的唯讀 badge。尚未知或尚未取得資料時顯示 --；其他型號不顯示此 badge。

限制

不在 WebUI 介面範圍內的命令會由 /api/commands 標示停用，直接提交時回傳 not_implemented_in_webui。後端／Core 也會拒絕不支援型號、命令、模式與必要功能的直接請求；瀏覽器顯示不是安全邊界。

實機驗證 evidence 由 CLI suite artifact 記錄，不會因瀏覽器選擇器而建立或提升。權威命令清單請參閱 Product LIVE exact-scope matrix。目前連線範圍為：

  • E36312A：USB + system VISA；LAN + system VISA。
  • EDU36311A：USB + system VISA；LAN + system VISA。
  • E3646A：ASRL／RS-232 + system VISA。
  • PSM-2010：ASRL／RS-232 + system VISA。

只有 Core 精確矩陣中的命令會在上述連線開放。E3646A 與 PSM-2010 仍限於 ASRL／RS-232 + system VISA；兩者的 USB 與 LAN 不在目前範圍內。PSM-2010 開放 Core Product matrix 中確切的 23 個 model-aware commands，涵蓋 setpoint／output、protection、snapshot／restore、ramp 與 software-sequence workflows；Powers Trigger commands 維持不支援。

E36312A 的 full 在 read-only、output、protection、snapshot 與 trigger-list suites 外包含 software-sequence；EDU36311A 的 full 在 read-only、output 與 protection 外包含 software-sequence，其 trigger/native LIST 與 snapshot/restore 維持停用。E3646A 的 full 仍是 readonly、output 與 software-sequence；其 ramp-list 與 sequence 是軟體工作流程而非 native LIST，protection、trigger/native LIST、snapshot/restore 與 completion-pulse 維持停用。WebUI expected-model 欄位只是 safety guard 與 planning hint，不會改變 IDN 選出的 live driver，也不會讓瀏覽器開啟不同連線類型。

測試

uv run python -m pytest tests/webui -q -p no:cacheprovider

焦點指令分類與工作接收驗證：

.\.venv\Scripts\python.exe -m pytest tests\webui\test_webui_api_jobs.py -q -p no:cacheprovider

WebUI 工作測試（tests/webui/test_webui_api_jobs.py）包含 Core → WebUI 指令分類 drift guard，確保 COMMAND_CONTRACTS 中的所有正式 Core 指令皆明確劃分於 SHARED_CORE_COMMANDS 或 WEBUI_UNSUPPORTED_COMMANDS，防止無聲遺漏或重疊。

聚焦 launcher 與套件驗證：

.\.venv\Scripts\python.exe -m pytest tests\webui\test_launcher.py tests\webui\test_webui_import.py tests\core\test_distribution_metadata.py -q -p no:cacheprovider

編輯 WebUI JavaScript 後，另執行：

node --check src\powers_tool_webui\static\execution-context.js
node --check src\powers_tool_webui\static\electrical.js
node --check src\powers_tool_webui\static\app.js

可行時執行更廣泛的無硬體驗證：

uv run python -m pytest tests -q -p no:cacheprovider

從 locked development environment 建置本機 shared Windows onedir bundle：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_windows_bundle.ps1
.\dist\powers-tool\powers-tool-webui-launcher.exe --version

數字欄位限制來自共用的 Commands parameter contract。辨識資源型號後，UI 會套用已驗證的官方獨立通道直流輸出額定值；未知型號不會被套用臆測限制，Core 仍是最終權威。
